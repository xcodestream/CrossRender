# Стандарт документации

Этот файл описывает, как устроена документация в `docs/`. Любой новый файл
должен следовать ему без исключений — иначе `python3 tools/doccheck.py` вернёт
ошибку.

## Структура

Документация повторяет дерево публичных заголовков:

```
engine/include/crossrender/<модуль>/<Header>.h   ->   docs/<модуль>/<Header>.md
```

Один файл документации описывает **один заголовок**. Если в заголовке
несколько классов, в файле сначала идёт обзор, затем раздел на каждый класс.

## Язык

Весь текст — **на русском языке**. Английскими остаются только:

* имена классов, методов, полей и типов (они являются частью API);
* ключевые слова C++;
* имена файлов и пути;
* общепринятые термины (shader, фреймбуфер, вершинный буфер) — при первом
  употреблении даётся русское пояснение в скобках.

Комментарии внутри примеров кода — **на русском**.

## Раздел на каждый публичный член

Каждый публичный метод и каждое публичное поле получает **свой** подраздел
`###` со сигнатурой в обратных кавычках и **примером кода на C++**:

```markdown
### `bool Init()`

Создаёт внутренние ресурсы. Безопасно вызывать повторно — второй вызов
ничего не делает и возвращает `true`.

* **Возвращает:** `true`, если рендерер готов к работе.
* **Контекст:** требует текущего контекста OpenGL.

```cpp
crossrender::Renderer2D r2d;
if (!r2d.Init()) {
    ENG_LOGE("demo", "не удалось инициализировать 2D-рендерер");
    return;
}
```
```

Правила:

1. Заголовок `###` начинается с сигнатуры в обратных кавычках — так, как она
   выглядит в заголовке (можно опустить `[[nodiscard]]`).
2. Внутри подраздела обязателен **хотя бы один блок ```cpp**: минимальный, но
   осмысленный вызов именно этого члена, при необходимости с проверкой
   результата.
3. Если у члена есть параметры — либо опишите их списком, либо покажите в
   примере так, чтобы назначение каждого было очевидно.
4. Перегрузки документируются отдельными подразделами, если поведение
   отличается, и одним подразделом с общим примером, если различается только
   тип аргумента (в этом случае перечислите варианты в тексте).
5. Для больших перечислений (enum) и наборов констант допускается один
   подраздел **на перечисление** с таблицей значений и примером использования;
   каждая отдельная константа описывается строкой таблицы.
6. Приватные члены, `Impl`-структуры и детали реализации не документируются.

## Проверка

```bash
python3 tools/doccheck.py           # все проверки
python3 tools/doccheck.py -v        # ещё и статистика по файлам
```

Скрипт проверяет:

* в каждом файле есть кириллица (текст действительно русский);
* число блоков ```cpp не меньше числа подразделов `###`;
* каждый подраздел `###` содержит пример;
* идентификаторы из заголовков `###` встречаются в `engine/include`;
* каждый публичный класс движка упомянут хотя бы в одном файле.

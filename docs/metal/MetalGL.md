# Metal compatibility layer (GL поверх Metal)

Прослойка `engine/metal/` даёт сборкам macOS и iOS режим «backend Metal»:
движок продолжает работать через обычные вызовы OpenGL (`gl::`), но при
`CR_METAL=ON` каждая точка входа разрешается в Metal-реализацию из этой папки.
Сторонние библиотеки не используются — только системные фреймворки Metal и
QuartzCore.

## Состав

| Файл | Назначение |
|---|---|
| `MetalTypes.h/.cpp` | таблицы соответствий: форматы текстур, вершинные атрибуты, примитивы, блендинг, compare-функции (GL → Metal) |
| `ShaderTranslate.h/.cpp` | рантайм-конвертер шейдеров GLSL → MSL для диалекта движка; юниформ-буферы стадий биндятся со слота `[[buffer(16)]]`, не пересекаясь с вершинными данными; чистый C++, тестируется на всех платформах |
| `MetalContext.h` | интерфейс контекста/поверхности для платформенного кода |
| `GLToMetal.mm` | реализации подмножества GL поверх Metal: ресурсы, состояние, рендер-пассы, вывод в `CAMetalLayer` |
| `MetalLoader.h/.cpp` | подмена таблицы `gl::LoadFunctions`: реализованные имена → Metal-версии, остальные — типизированные no-op заглушки |

## Как это работает

1. Окно (macOS: `WindowMacOS.mm`, ветка `ENG_METAL`) подставляет `CAMetalLayer`
   вместо `NSOpenGLContext` и вызывает `mtlgl::AttachLayer()`.
2. `gl::LoadFunctions()` (ветка `ENG_METAL` в `Log.cpp`) заполняет таблицу из
   `mtlgl::ResolveGLProc()` — движок ничего не замечает.
3. `glCompileShader` прогоняет исходник через `TranslateGLSLToMSL()` и собирает
   MSL через `[MTLDevice newLibraryWithSource:]`.
4. `glLinkProgram` запоминает таблицу юниформов; `glUniform*` пишет в staging
   (слот юниформа = `[[buffer(k)]]` своей стадии, сэмплеры — `[[texture(i)]]`
   + `[[sampler(i)]]`); на `glDraw*` чанки загружаются и биндятся.
5. Рендер-пасс открывается лениво на первую отрисовку против активного
   фреймбуфера (drawable окна или цель FBO) и закрывается при смене цели
   (`glBindFramebuffer`) и на `Present()` (аналог `SwapBuffers`).

## Сборка

```bash
./build.sh --metal            # macOS, рендер через прослойку
./build.sh ios --metal        # iOS, слой компилируется в библиотеку
cmake -B build/host -DCR_METAL=ON   # напрямую через CMake
```

Без `--metal` ничего не меняется: слой не собирается, движок работает на GL.

## Покрытие и ограничения (честно)

Реализовано: буферы, текстуры (RGBA8/BGRA8/R8/16F/32F + depth), программы с
конвертацией шейдеров, VAO/атрибуты (включая interleaved-потоки), блендинг,
scissor/depth/cull, FBO RGBA8/16F, `ReadPixels`, same-size
`BlitFramebuffer`, вывод в окно через `CAMetalLayer`. Ретро-пайплайн
(retro-pixel) компилируется: `texelFetch` → `.read()`, хелпер-функции,
использующие юниформы, получают блок `UniformsFS` дополнительным параметром.

Пока не реализовано (вызовы деградируют в no-op с подсчётом): stencil-clip
путей 2D-рендерера, instancing (>1), MSAA, mipmap-генерация, query-объекты,
multisample renderbuffers. Ограничения конвертера: массивы юниформов с
не-16-байтовым шагом (`vec3`-массивы), `mat3` в constant-памяти Metal
выравнивается по 16 байт против 12 у GL. Юниформ-буферы стадий биндятся
со слота `[[buffer(16)]]` и выше — слоты 0..15 оставлены вершинным данным.

Тесты конвертера и таблиц: `tests/test_metalgl.cpp` (запускается на всех
платформах). Интеграционная проверка рендеринга — запуск примера с
`CR_METAL=ON` на Apple-железе.
